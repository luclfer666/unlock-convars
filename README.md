# convars

Модуль для **Deadlock**, который добавляет в игру своё меню. Через него можно подправить угол обзора (FOV), соотношение сторон и убрать лишнюю графику — прямое освещение и небо.

## Что умеет

| Раздел меню | Что делает |
|---|---|
| **FOV Changer** | Меняет угол обзора (40–165) и соотношение сторон. При выключении возвращает те значения, что прописаны в `gameinfo.gi` игры |
| **Rendering** | `Direct Lighting` — убирает прямое освещение. `Skybox` — убирает небо |

Всё в меню работает на живом процессе: включили тумблер — эффект применился сразу.

## Два способа запуска

В проекте две программы-загрузчика. Делают одно и то же — грузят `dysonbehind.dll` в игру, — но выглядят по-разному. Выбирайте одну, не запускайте обе сразу.

| | `Injector.exe` | `Injector Tray.exe` |
|---|---|---|
| Как выглядит | Чёрное консольное окно с логом | Иконка в трее, окон нет |
| Запуск игры | Сам открывает Deadlock через Steam, если он не запущен | Так же |
| Управление функциями | Меню в игре, клавиша `Insert` | Контекстное меню по клику на иконку в трее |
| Меню в игре | Работает | Не открывается — в трей-режиме `Insert` отключён, чтобы меню не всплывало поверх |
| Обновления | Проверяет и предлагает скачать новую версию | Не проверяет |
| Закрытие | Вручную, крестиком консоли | `Exit + kill game` в меню трея, либо сам закрывается, когда игра вышла |

**Иконка трея:** левый клик или правый клик по ней — открыть меню. Меню «липкое»: можно щёлкать тумблеры и пункты один за другим, оно закроется только когда вы кликнете мимо него или нажмёте `Esc`.

```
starting injection...          ← статус серым
─────────────────────────────
FOV Changer               ▸
   ├ Enabled
   ├ Field of view  (120)  ▸  90 / 100 / 105 / 110 / 115 / 120 / …
   └ Aspect ratio  (1.50)  ▸  Native / 1.33 / 1.50 / 1.60 / 1.78 / 2.00 / 2.35 / 3.00
Rendering                 ▸
   ├ Direct Lighting
   └ Skybox
─────────────────────────────
Exit + kill game
```

Выбор пресета FOV или аспекта сам включает нужный тумблер — отдельно тыкать `Enabled` не надо.

`Exit + kill game` закрывает игру и следом закрывает трей.

## Способ загрузки модуля

Оба загрузчика кладут `dysonbehind.dll` в игру одним способом — **manual map**. Это ручная загрузка: загрузчик сам разбирает DLL и раскладывает её по памяти игры, не спрашивая Windows, и отдельно заводит ей TLS. В списке модулей процесса после этого её не видно. Права администратора нужны: без них запись в чужой процесс не сработает.

У способа есть цена — он опирается на внутренности загрузчика Windows. Перед мапингом загрузчик проверяет, что в `ntdll.dll` на месте внутренняя функция, через которую Windows заводит TLS. Если её там нет (например, Microsoft переставила код в новом билде), загрузчик не станет мапить вслепую: он откажется и напишет в лог, что ручная загрузка на этой сборке Windows невозможна. Иначе модуль загрузился бы «успешно», но упал бы позже, на первом же обращении к своим статическим переменным.

Другого способа в проекте нет: если manual map на вашей системе не работает, загрузить модуль не получится.

Manual map не делает загрузку невидимой: он убирает один самый простой признак — модуль в списке загруженных библиотек. Хуки внутри игры он ставит теми же байтами, что и обычная загрузка, так что «теперь точно не забанят» он не гарантирует.

Путь к DLL можно задать аргументом: `Injector.exe D:\папка\dysonbehind.dll`. Если рядом лежит `inject.bat`, можно просто перетащить DLL на него.

## Состав релиза

Все файлы должны лежать в одной папке — загрузчик ищет `dysonbehind.dll` рядом с собой.

```text
release/
├── Injector.exe          ← консольный загрузчик
├── Injector Tray.exe     ← загрузчик в трее (можно не ставить, если не нужен)
├── dysonbehind.dll       ← сам модуль
└── debug/                ← сюда пишутся логи, создаётся автоматически
```

Не переименовывайте `dysonbehind.dll` и не раскладывайте файлы по разным папкам.

## Установка и запуск

1. Скачайте актуальный архив релиза и распакуйте в отдельную папку.
2. Закройте Deadlock, если он запущен. Так загрузчик дождётся свежего процесса и попадёт в него, а не в старый.
3. Запустите `Injector.exe` или `Injector Tray.exe` **от имени администратора**. Без прав администратора загрузка в чужой процесс не сработает.
4. Дождитесь сообщения об успешной загрузке. Если Deadlock не был запущен, загрузчик откроет его сам через Steam.
5. Откройте меню в игре клавишей `Insert`.

При успешной загрузке консольный загрузчик напишет:

```text
[+] Injected. INSERT toggles menu in game.
```

### Проверка обновлений

`Injector.exe` при старте проверяет GitHub на новую версию. Чтобы не ждать таймаута сети, нажмите `Enter` или `Esc` — проверка прервётся сразу.

Если версия новее — загрузчик предложит открыть страницу релиза. Файлы сами не скачиваются и не подменяются.

Если GitHub недоступен, проверка просто пропускается и запуск идёт как обычно.

## Управление в игре

| Клавиша | Назначение |
|---|---|
| `Insert` | открыть или закрыть меню |
| `Delete` | то же самое, альтернативная клавиша |
| Левая кнопка мыши | тумблеры и выбор пунктов |

Пока меню открыто, курсор отдаётся интерфейсу. Закрыли меню — управление мышью вернулось игре.

Меню само открывается при входе в матч — просто чтобы показать, что модуль жив.

В трей-режиме (`Injector Tray.exe`) этого не происходит: и `Insert`, и автооткрытие выключены, а колонки в меню подсвечены серым с подписью `controlled from tray`.

## FOV Changer

1. Включите тумблер `FOV Changer`.
2. Двигайте `Field of view` (40–165) и `Aspect ratio` (0.50–3.00).
3. `Custom Aspect` — разрешает аспекту не сбрасываться на `1.50`, когда вы отпускаете слайдер.

Значение по умолчанию — `120`. Для сравнения, штатный угол обзора игры — `75`, подсказка об этом всплывает при наведении на слайдер.

**Как выключается.** Когда вы снимаете тумблер, модуль не ставит дефолт движка, а возвращает то, что прописано в `gameinfo.gi` самой игры (`citadel_camera_hero_fov`, `fov_desired`, `r_aspectratio`). Файл ищется подъёмом вверх от `client.dll` — обычно это `game/citadel/gameinfo.gi`. Если файл не найден или параметра в нём нет, берётся дефолт движка. Что именно подставилось, видно в логе:

```text
[+] FOV Changer: off -> fov_desired 75.0 (gameinfo) / hero_fov 90.0 (gameinfo) / aspect native
```

`gameinfo` в скобках — взято из файла, `engine default` — файла не было.

## Rendering

Два независимых переключателя, работают сразу, перезапуск не нужен.

| Пункт | Что убирает |
|---|---|
| `Direct Lighting` | Прямое освещение — картинка становится плоской и темнее |
| `Skybox` | Небо — вместо него чёрный фон |

Оба сделаны на конварах движка `r_directlighting` и `r_drawskybox`. При снятии галочки модуль возвращает конвару исходное состояние.

## Логи и диагностика

Логи складываются в подпапку `debug/` рядом с программой. Папка создаётся сама при первом запуске, и старые логи из корня переезжают туда же автоматически.

```text
debug/
├── dysonbehind_debug.txt      ← модуль внутри игры
├── injector_debug.txt         ← Injector.exe
└── injector_tray_debug.txt    ← Injector Tray.exe
```

По логам видно:

- нашлась ли игра и с каким PID;
- успешно ли загрузилась DLL;
- дождалась ли DLL игровых модулей и встали ли хуки;
- какие значения FOV выставлялись;
- применились ли `Direct Lighting` и `Skybox`.

### Меню не появилось

1. Проверьте, что загрузчик запущен **от имени администратора**.
2. Проверьте, что `dysonbehind.dll` лежит рядом с ним и относится к той же версии.
3. Закройте Deadlock и запустите загрузчик заново.
4. Попробуйте `Insert` и `Delete` после полной загрузки игры.
5. Если пользуетесь трей-версией — откройте меню через иконку в трее, `Insert` там отключён специально.
6. Смотрите `debug/dysonbehind_debug.txt` и `debug/injector_debug.txt`.

В логе модуля строка `InitThread: dll_dir=...` показывает, откуда он взял свою папку, и стоит ли там `manual_map=1`. Если видите `manual_map=0` — папку модуль определил не по подсказке загрузчика, а сам; так бывает, когда DLL положили в игру не нашим загрузчиком.

### Загрузка не сработала

1. Посмотрите `debug/injector_debug.txt` или `debug/injector_tray_debug.txt`:
   - `ntdll TLS handler not resolvable` — ручная загрузка на вашей сборке Windows невозможна: загрузчик не нашёл внутреннюю функцию, через которую Windows заводит TLS, и отказался мапить. Другого способа загрузки в проекте нет;
   - `ManualMapDll failed` — модуль не разложился по памяти;
   - `handoff NOT accepted` — модуль загрузился, но не смог определить свою папку. Скорее всего версии загрузчика и DLL не совпадают, а без папки модуль не пишет логи вообще.
2. Антивирус может мешать записи в чужой процесс — добавьте папку с игрой и загрузчиком в исключения.
3. Мелочь, но проверьте: файл `dysonbehind.dll` не должен быть повреждён — размер должен совпадать с тем, что в релизе.

### FOV не вернулся при выключении

1. Посмотрите в `debug/dysonbehind_debug.txt` строку `FOV Changer: gameinfo ...` — там видно, нашёлся ли файл.
2. Если в логе `engine default`, значит `gameinfo.gi` не найден или в нём не оказалось нужных строк — тогда подставляются дефолты движка, и это нормально.

## Обновления и релиз

Текущая версия прописана в `src/injector.cpp`:

```cpp
static constexpr const char* CURRENT_VERSION = "1.0.5";
```

Проверяется GitHub Releases API репозитория:

```text
https://github.com/luclfer666/unlock-convars/releases
```

Порядок выпуска новой версии:

1. поднимите `CURRENT_VERSION` в `src/injector.cpp`;
2. соберите `dysonbehind.dll`, `Injector.exe` и `Injector Tray.exe`;
3. создайте GitHub Release с тегом, совпадающим с версией, например `1.0.5`;
4. приложите к релизу собранные файлы или архив;
5. у себя замените файлы в папке.

## Сборка из исходников

### Что нужно

- Windows 10 или 11;
- Visual Studio с MSVC и Windows SDK, компонент `Desktop development with C++`;
- CMake 3.20 или новее;
- Steam с установленным Deadlock — чтобы было куда грузить модуль.

### Быстрая сборка

Из корня проекта:

```text
build.bat
```

Скрипт сам найдёт Visual Studio, настроит каталог `build`, соберёт `Release` и разложит готовые файлы по `release/`.

### Сборка вручную

```text
cmake -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

Готовые файлы появляются в `build/Release/` и копируются в `release/`:

```text
build/Release/dysonbehind.dll
build/Release/Injector.exe
build/Release/Injector Tray.exe
```

Собирать можно и по отдельности:

```text
cmake --build build --target dysonbehind  --config Release
cmake --build build --target Injector   --config Release
cmake --build build --target InjectorTray --config Release
```

### Из чего состоит проект

```text
src/                  код модуля (dysonbehind.dll) и консольного загрузчика
injector_tray/        код трей-загрузчика (Injector Tray.exe)
vendor/               imgui, minhook и manualmap
injector_tray/TrayMenu.cpp   меню в трее, если захотите добавить пункт
src/Bridge.h          общий формат памяти между треем и модулем
src/LogPath.h         куда класть логи
src/MapHandoff.h      что загрузчик передаёт модулю при ручной загрузке
src/ModulePath.h      откуда модуль узнаёт свою папку
src/ManualMapProbe.h  проверка, что ручная загрузка вообще сработает
```

## Встроенные ресурсы

Звуки меню, шрифты и иконки зашиты внутрь `dysonbehind.dll` — отдельных файлов рядом с релизом не требуется.

- открытие и закрытие меню;
- выбор пункта;
- включение и выключение тумблера.

## Совместимость

Проект держится на внутренних сигнатурах Deadlock. После крупного обновления игры функция может временно отвалиться, пока сигнатуры не обновят под новый билд. Признак — сообщение о ненайденном паттерне в `debug/dysonbehind_debug.txt`.

Загрузчик и модуль должны быть одной версии. Не грузите DLL в другой процесс вручную и не запускайте два загрузчика одновременно.
